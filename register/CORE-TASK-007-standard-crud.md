**Кому:** Управляющий чат утилиты Register

## Что сделать

Реализовать серверную логику (API) для управления Проектными стандартами (`project_standard`) и их составом сигналов (`project_standard_signal`).
*Напомним: сущность `project_standard` — это шаблон сигналов для конкретной модели прибора (например, для модели «Датчик давления»).*

## Зачем

Это необходимо для того, чтобы инженер мог создавать модели приборов, а затем мы могли перейти к созданию интерфейса (UI) и полноценному тестированию.

## Ключевое правило (CORE-ADR-015)

При обновлении (`PUT`) проектного стандарта:
1. Изменять название или значения по умолчанию — **можно**.
2. Изменять состав сигналов (`project_standard_signal` — добавлять/удалять) — **запрещено, если к этому стандарту привязан хотя бы один прибор** (выдавать `409 Conflict` с понятным сообщением).
3. Для изменения состава инженер должен создать новый стандарт для этой модели.

## Критерии готовности

1. Реализован `POST`, `GET` (список и по ID), `PUT`, `DELETE` для `project_standard`.
2. Реализовано управление составом `project_standard_signal` (создание/удаление сигналов в стандарте) с учетом правила ADR-015.
3. Написаны Unit-тесты (включая сценарий запрета изменения состава при наличии приборов).
4. Проведено независимое Black-box тестирование (Level 2).
5. Обновлен `CHANGELOG.md`.
6. Сделан коммит.

## Ограничения
- Не писать интерфейс (UI).
- `GET /api/signals/<id>` пока не делаем.
