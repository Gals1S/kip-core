# Задание: Реализация CRUD для справочников

**Проект:** KIP_register
**От кого:** Управляющий чат Core
**Кому:** Управляющий чат утилиты Register

## Что сделать

Реализовать серверную логику (API и работу с БД) для управления справочниками (создание, чтение, обновление, удаление). 
**Внимание:** Интерфейс пользователя (HTML/JS) на этом шаге делать не нужно, только серверную часть (Backend).

## Зачем

Справочники (типы приборов, модели, IP, Ex, материалы и т.д.) — это фундамент. Без них невозможно заполнить карточку прибора или сигнала, и нельзя переходить к следующему этапу.

## Контекст (Lean-загрузка)

Для выполнения задачи тебе потребуется структура таблиц справочников. Прочитай `REG-ARCH-db.md` (раздел 3 «Справочники»). 
Если для реализации логики (валидации, связей) тебе понадобятся другие файлы (например, `REG-SPEC.md`), **запроси их у арбитра**. Не пытайся угадать или работать по памяти.

## Специальное указание (Анти-лень)

Включи режим строгого критика. Не срезай углы, не используй заглушки. Обработка ошибок (например, попытка добавить дубликат записи) должна быть реализована полноценно, в соответствии с ограничениями (UNIQUE constraints) из архитектуры БД.

## Критерии готовности

1. Код реализован согласно выбранному стеку (Python/Flask/SQLAlchemy).
2. Написаны модульные тесты (Unit-тесты) для всех операций CRUD.
3. Сформирована **«Карта контрактов»** для независимого тестирования.
4. Сделан коммит.

## Ограничения

- Не писать интерфейс (UI).
- Не менять структуру БД (миграции уже готовы).
- Не писать тесты «наугад» — ожидаемые значения в тестах должны строго соответствовать бизнес-правилам.

## Формат результата

Верни отчет о завершении по шаблону `CORE-HANDOFF-template.md`. В разделе «Доказательства» укажи хеш коммита.

## Порядок работы (строго по шагам)

1. Изучи раздел «Справочники» в `REG-ARCH-db.md`.
2. Предложи арбитру план реализации (структуру файлов и список API-эндпоинтов). Жди ответа.
3. Напиши код.
4. Напиши Unit-тесты к коду. Проверь, что они проходят.
5. Сгенерируй «Карту контрактов» (сигнатуры функций и описание их поведения) для передачи независимому тестировщику.
6. Сделай коммит и сформируй отчет.
