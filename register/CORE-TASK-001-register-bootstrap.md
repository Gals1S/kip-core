# Задание: Создание каркаса проекта KIP_Register

**Файл:** `CORE-TASK-001-register-bootstrap.md`
**Проект:** KIP_register
**От кого:** Управляющий чат Core
**Кому:** Управляющий чат утилиты Register
**Дата:** 09.11.2026

---

## Что сделать

Создать базовый каркас проекта KIP_Register: папки, документацию, настройку Git. На этом этапе **не пишем код приложения и не проектируем базу данных**. Только фундамент для дальнейшей работы.

## Зачем

Чтобы обеспечить единообразие документирования и организации работ между Core и утилитами. Register станет первым продуктовым чатом, который должен следовать правилам экосистемы с самого первого дня.

## Контекст

Core передаёт тебе правила работы и архитектурные документы. Прочитай их внимательно перед началом. 
Обязательные документы, которые нужно изучить:
- `handover.md` — правила работы (особое внимание разделу 5 «Документация утилит»).
- `SPECIFICATION.md` — контракт экосистемы (текущая редакция v1.1).
- `CORE-ARCH-data-model.md` — модель данных проекта.
- `CORE-ARCH-data-flow.md` — как Register взаимодействует с Reader и Generator.
- `templates/CORE-HANDOFF-template.md` — по этому шаблону ты будешь отчитываться.

Обрати внимание на правила ведения дневников. По правилам Core (`handover.md`, раздел 5) каждая утилита обязана вести дневник сессий в папке `docs/diary/`. Дневник не является критерием сдачи задания (так как задача может быть выполнена раньше, чем закончится сессия), но ты должен подтвердить в своём Отчёте о завершении, что принял это правило к исполнению.

## Критерии готовности

Задание считается выполненным, когда в проекте KIP_Register:
1. Инициализирован Git (`git init`).
2. Создана папка `docs/`.
3. Создан `README.md` — визитка утилиты (назначение, функции).
4. Создан `handover.md` — правила работы утилиты. Он должен **дополнять** Core (специфика Register), а не повторять его.
5. Создан `<UTIL>-SPEC.md` (например, `REG-SPEC.md`) — описание утилиты. Обязательно укажи ссылку на контракт Core: «Контракт — KIP_Core v1.1».
6. Создана папка `docs/decisions/` и в ней реестр `<UTIL>-ADR-REGISTRY.md` (пустая таблица по образцу Core).
7. Создана пустая папка `docs/diary/` (место для будущих дневников сессий).
8. Сделан первый коммит с осмысленным сообщением по формату Core.

## Ограничения

- Не писать код на Python/Flask на этом этапе.
- Не создавать схему БД.
- Не придумывать структуру папок для кода (`src/`, `tests/` и т.д.) — это будет на следующей вехе, когда определимся со стеком.

## Формат результата

Верни **Отчёт о завершении** по шаблону `CORE-HANDOFF-template.md`. В разделе «Доказательства» перечисли созданные файлы и укажи хеш первого коммита.

## Порядок работы

1. Сначала предложи арбитру план действий (какие папки и файлы создашь).
2. После одобрения создай файлы.
3. Напиши текст для сохранения файлов (если работаешь через чат), либо укажи команды для терминала.
