# Задание: Выбор стека и проектирование базы данных

**Проект:** KIP_register
**От кого:** Управляющий чат Core
**Кому:** Управляющий чат утилиты Register
**Дата:** 09.11.2026

---

## Что сделать

Выбрать технологический стек для разработки (язык, фреймворк, СУБД), спроектировать структуру базы данных на основе модели Core и создать скрипты инициализации/миграции.

## Зачем

Чтобы начать программировать логику утилиты, нужен фундамент: структура хранения данных, которая точно соответствует контракту Core.

## Контекст

- Модель данных, которую нужно реализовать: `CORE-ARCH-data-model.md`.
- Поведение утилиты (что она делает): `REG-SPEC.md`.
- Правила работы: `handover.md` (Core и утилиты).

Обрати внимание: в модели есть трехуровневое наследование (справочник → стандарт → прибор) и связь many-to-many (сигналы ↔ сегменты). Спроектируй структуру так, чтобы это было удобно и производительно.

## Критерии готовности

1. Выбран и обоснован стек (язык, фреймворк, СУБД). Решение зафиксировано в архитектурном документе или первом ADR утилиты.
2. Создан архитектурный документ `REG-ARCH-db.md` с описанием структуры таблиц и связей между ними.
3. Написаны скрипты (миграции/DDL) для создания структуры БД.
4. Создана структура папок для кода (`src/`, `tests/` и т.д.), соответствующая выбранному стеку.
5. Сделан коммит.

## Ограничения

- **Не писать код интерфейса и бизнес-логику (CRUD)**. Только структура БД и миграции.
- Не менять модель данных Core. Если кажется, что чего-то не хватает — стоп, запрос в Core.

## Формат результата

Отчёт о завершении по шаблону `CORE-HANDOFF-template.md` с указанием хеша коммита.

## Порядок работы (ВАЖНО)

Работай строго по шагам, дожидаясь подтверждения от арбитра после каждого:
1. Предложи варианты технологического стека (язык, СУБД) с кратким обоснованием. Жди ответа.
2. После выбора стека предложи структуру таблиц (сущности, поля, связи). Жди ответа.
3. После одобрения схемы напиши скрипты создания БД и создай структуру папок.
