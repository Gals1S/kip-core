## Зачем

Для предсказуемости API и удобства будущего фронтенда. Системные имена ограничений БД не должны попадать в ответы API.

## Критерии готовности

1. **П.2 (Запрет системных имен):** Вместо `{"constraint": "ck_..."}` API должно возвращать стандартизированный формат `{"code": "...", "message": "..."}` (например, `code: "range_error"`).
2. **П.3 (Единообразие `ref`):** Для `project_standard_id` в ошибках FK использовать `ref: "project-standard"` (kebab-case), как у справочников.
3. **П.4 (Race-ветка 409):** Ошибки 409 при race-condition должны иметь точно такой же формат (`unique` + `values`), как при штатной проверке уникальности.
