## 1. Что сделано

**CRUD приборов (`src/kip_register/devices/service.py`, `src/kip_register/api/devices.py`).**
- 5 эндпоинтов: `GET/POST /api/devices`, `GET/PUT/DELETE /api/devices/<id>`.
- Валидация полей (типы, длины, FK, CHECK `range_max >= range_min`), уникальность `tag` двумя слоями.
- Аудит: `created_by`/`updated_by` = `"system"` (заглушка), даты ISO 8601 UTC.

**Наследование от проектного стандарта.**
- 9 наследуемых полей: `NULL` в `device` → из стандарта, значение → override.
- GET/POST/PUT возвращают **эффективные значения** в основных полях + `overrides` — список переопределённых полей.
- PUT: не передано → не трогать; значение → override; `null` → сброс override.
- Смена `project_standard_id`: переопределения сохраняются, остальное пересчитывается.
- Поля уровня 3 (диапазон, параметры процесса, закупка, монтаж) не наследуются, `null` = пусто.

**JSON-провайдер.**
- `Decimal` → `float` (numeric-поля прибора).
- `datetime` → ISO 8601 **UTC** (`astimezone(timezone.utc).isoformat()`) — исправление находки №1.

## 2. Что найдено в процессе (важно)

**Независимое тестирование выявило 1 расхождение — исправлено.**
- **Находка №1 — даты с локальным смещением `+03:00` вместо `+00:00`.** Контракт (раздел 1) требует «смещение `+00:00`». Причина: `psycopg3` возвращает `timestamptz` с локальной зоной процесса; `isoformat()` давал `+03:00`, хотя в БД — UTC. Исправлено в `ISO8601JSONProvider`: `astimezone(timezone.utc)` перед `isoformat()`. Покрывает все эндпоинты (и справочники). Перепрогон: 129/129 независимых, 370/370 суммарно.
- **Моя ошибка в ответе на шаг 9:** утверждал «`+00:00` всегда», не проверив фактическую сериализацию. Тестировщик поймал — ровно то, ради чего Level 2. Впредь по форматам — проверка фактическим запросом до ответа.

**Ошибка при создании прибора (найдена нашими тестами).**
- `device` не наследует `AuditMixin` (миксин только у справочников); `created_at`/`updated_at` — `NOT NULL` без `server_default`. `create_item` ставил только `created_by`/`updated_by`, не даты → NOT NULL violation. Исправлено: явное заполнение дат в `create_item`.

**Пробелы контракта (21, зафиксированы в `REG-CONTRACT-devices.md`, раздел 9).** Существенные (5):
- **strip-нормализация** строк: `value.strip()` до проверки и записи; `" "` → 400; в БД — stripped. Контракт не оговаривает.
- **точное значение `details.constraint`** (`"ck_device_range_max_ge_min"`) — контракт фиксирует только наличие.
- **`ref` для `project_standard_id`** — `"project_standard"` (snake_case, имя таблицы), для справочников — kebab-case URL. Несогласовано.
- **race-ветка 409** — `details.constraint` вместо `unique`/`values`; невоспроизводима в black-box.
- **`device_document` RESTRICT при DELETE** — FK без CASCADE; поведение при связанных документах не оговорено (сейчас строк нет, не проявляется).

**Несущественные (16):** формат фикстур, диапазон limit/offset, `""` в наследуемом строковом, NaN/Infinity, порядок CHECK, `cable_entry_count < 0`, регистр полей, DELETE с query/телом, микросекунды, монотонность `updated_at`, `created_at == updated_at` при POST, значения `created_by`/`updated_by`, `_clean_tables`, `Tag` регистр, `ref` справочников, характеризационные аспекты.

## 3. Что требует внимания

- **История переопределений (`device_override_history`)** — вынесена отдельной задачей (решение Core). Требование модели «отслеживаемо» выполняется частично: `updated_by`/`updated_at` на `device`, без «что изменил». Открытый пункт.
- **`device_document`** — CRUD документов прибора не реализован (отдельный ресурс). FK RESTRICT при DELETE прибора проявится, когда появятся строки.
- **Сигналы при смене стандарта** не пересоздаются — CRUD сигналов ещё нет. Когда появится, логика смены модели (пересоздание сигналов по стандарту) будет реализована там.
- **Существенные пробелы контракта (5)** — требуют уточнения до следующей итерации, иначе аспекты останутся непокрытыми строгими тестами. Не блокируют приёмку.
- **`Decimal` → `float` в JSON** — для измеряемых величин достаточно; для денежных понадобился бы строковый формат.
- **Синхронизация часов** между Python-процессом и PostgreSQL — `created_at`/`updated_at` ставятся Python-временем (`datetime.now(timezone.utc)`), не серверным `now()`. При развёртывании на другой машине — синхронизация.
- **CHANGELOG** — строка для дописи: `14.11.2026 | не выпущено | Добавлено | API приборов: создание, чтение, обновление, удаление; наследование характеристик от проектного стандарта с переопределениями`.
