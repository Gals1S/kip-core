## 2. Что найдено в процессе (важно)

**15 вопросов тестировщика — каждый реальная неоднозначность контракта, не «для галочки».** Существенные:
- **Порядок проверок описан как фазы, реализация — единый проход по полям.** Для `{"tag": null}` без `project_standard_id` контракт (фазы) ожидал бы `project_standard_id`, реализация даёт `tag`. Контракт переписан: unknown — предварительный проход, далее единый проход по полям (missing → null → type → FK), первое нарушение.
- **CHECK `range_max >= range_min` — к переданным полям или к итоговой строке.** Реализация — к итоговой строке (SQL CHECK); POST с одним полем → 201, PUT, делающий строку противоречивой → 400 `range_error`. В контракте не было — добавлено.
- **Нормализация в UNIQUE 409.** `" PT-1 "` и `"PT-1"` — дубликат; `values.tag` — нормализованное. Для refs зафиксировано ранее (Q7), для devices — добавлено (Q13).
- **«Не JSON-объект» — 5 сценариев** (невалидный JSON, пустое тело, чужой `Content-Type`, скаляр, массив) → 400 JSON без `details`, 415 не возвращается.
- **Внутри блока FK — порядок полей контракта, первый нарушенный.** Для `device-model` с двумя невалидными FK → `device_type_id`; для devices — `project_standard_id`.

**Два противоречия в контрактах, найденные тестировщиком и исправленные:**
- `created_by`/`updated_by` — раздел 8 говорил «= "system"» (строго), 9.2 п.11 — «строго только строка, не null». Правило строгости первично; раздел 8 исправлен (`055178d`).
- Таблица ошибок devices — не было строки «тело не JSON-объект» (в refs была), и FK был слит в одну строку вместо двух. Исправлено (`e56ca3f`, `4b9f3f3`).

**Технические находки:**
- **BOM в `REG-CONTRACT-devices.md`** — в начале файла `\ufeff`, виден в выводе как `﻿`. На чтение/тесты не влияет, но при редактировании может мешать. Не критично, зафиксировано.
- **PowerShell и backtick** — команды `-replace` с backtick не срабатывают (escape-символ). Обход: `.Replace()` или ручная правка. Зафиксировано для будущих сессий.

## 3. Что требует внимания

- **Race-ветки 409 не проверены Black-box** (`reference_error`, `duplicate_id`, `integrity_error`). Воспроизведение гонки требует параллельных транзакций — отдельный подход, вне black-box. Открытый пункт.
- **Независимые тесты v2** — `tests/independent/test_refs_api.py`, `test_devices_api.py`. При следующей итерации (новые эндпоинты) они станут регрессионным набором; при изменении формата ошибок — снова потребуют обновления.
- **`REG-CONTRACT-devices.md` с BOM** — желательно перезаписать в UTF-8 без BOM (как `pyproject.toml` в прошлой сессии). Не блокер.
- **CHANGELOG** — запись 15.11.2026 добавлена. Проверить, что формат соответствует правилу (лента, дописывание в конец).
- **Порядок полей в контракте как норматив FK-проверок** — теперь зафиксирован. Если в будущем порядок полей в `DEVICE_FIELDS`/`spec.fields` изменится, это изменит поведение FK-проверок; контракт надо будет обновить.
- **История переопределений, `device_document`, сигналы** — открытые пункты с прошлых заданий, не входят в 005.
