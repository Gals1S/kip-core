## 2. Что найдено в процессе (важно)

- **PostgreSQL 12 — системная установка, не портативная сборка.** На машине стоит `C:\Program Files\PostgreSQL\12` со службой `postgresql-12`. Это расходится с `REG-ADR-001` («портативная сборка для Windows, запуск без установки и прав администратора»). Для разработки работает; для поставки — нет. Версия 12 не поддерживается с ноября 2024.
- **Пароль `postgres` не был записан.** Сброшен через временную правку `pg_hba.conf` (`md5` → `trust` для локальных подключений), затем файл восстановлен из копии, служба перезапущена, вход с новым паролем проверен. Новые учётные записи: `postgres` / `Register_2026!`, `kip_register` / `KipReg_2026!`.
- **`configparser` падал на `%21` в URL.** Alembic хранит настройки через `configparser`, который интерпретирует `%` как подстановку; закодированный пароль ломал `set_main_option`. `env.py` переработан: движок создаётся напрямую из `REGISTER_DATABASE_URL`, минуя `configparser`.
- **Autogenerate не создал индексы на FK.** По `REG-ARCH-db.md` (раздел 10) все FK индексируются. Индексы добавлены централизованно в `models.py`, а не `index=True` в моделях: правится один файл, модели и БД остаются в синхронизации, autogenerate их не удаляет.
- **`REGISTER_DATABASE_URL` живёт только в текущем терминале.** При перезапуске терминала переменную надо задавать снова. `.env` пока не сделан.

## 3. Что требует внимания

- **Портативная сборка PostgreSQL не развёрнута и не проверена.** Открытый вопрос 4 из `REG-RSH-002` закрыт не полностью: миграция проверена на системном PostgreSQL 12, но не на портативной сборке. Требуется решение: развернуть портативную сборку и прогнать миграцию на ней — до начала поставки.
- **Версия PostgreSQL для поставки не определена.** 12 не поддерживается; нужен выбор (например, 16/17) и проверка портативной сборки этой версии.
- **Пароли в командах и учётных записях — для разработки.** Для поставки нужна отдельная схема (отдельный пользователь, пароль при развёртывании, не в коде).
- **`.env` не сделан.** `REGISTER_DATABASE_URL` задаётся вручную в каждом терминале. Нужен файл `.env` в корне (он уже в `.gitignore`) и загрузка при старте приложения.
- **`tests/` пустая.** По заданию тесты не требовались — только структура папок. Тесты появятся на шаге бизнес-логики.
- **CHANGELOG не нужен.** Коммит технический: поведение программы для пользователя не меняется.
- **Дневник сессии не сформирован.** Нужно время окончания сессии для `docs/diary/2026-11-10-diary.md`.
