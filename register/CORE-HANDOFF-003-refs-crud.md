## 2. Что найдено в процессе (важно)

**Независимое тестирование выявило 3 расхождения с контрактом — все исправлены.**

- **Q4 — no-op PUT не менял `updated_at`.** SQLAlchemy не эмитит UPDATE при идентичных значениях, `onupdate` не срабатывал. Нарушение п. 2.5 контракта. Исправлено: `updated_at` выставляется явно в `update_item`. Решение B (контракт в силе, чинить код).
- **Q13 — 409 при частичном PUT не содержал `unique`/`values`.** `_check_unique` срабатывал только для полных групп; частичная группа ловилась на уровне БД, `details` содержал недокументированное `operation`. Нарушение п. 3.1. Исправлено: `_check_unique` подставляет текущие значения непереданных полей группы; `operation` убран. Решение B.
- **Q15 — `id ≥ 2 147 483 648` давал 500 `integer out of range`.** `session.get` с id вне диапазона PostgreSQL INTEGER падал на драйвере. Нарушение Q7 («любой невалидный id → 404»). Исправлено: guard диапазона в `get_item`. Решение A (404 — целевое).

**Пробелы контракта (закрыты по итогам тестирования):**
- `total` при `limit=0` — закрыт п. 2.2 (ключ всегда, полное число).
- 409 UNIQUE при частичном PUT — закрыт п. 3.1 (обновлён).
- `updated_at` при no-op PUT — закрыт реализацией.
- Поля аудита в теле — 400 «Неизвестные поля», одинаково для POST/PUT.
- `id` вне диапазона INTEGER — 404.

**Пробелы контракта (приняты как есть, 10 пунктов, раздел 8.2):** формат дат (RFC 822, до секунд), парсинг `limit`/`offset` (Python `int`), дефолт без `limit`, ключ nullable-поля в ответе, тело DELETE, порядок записей, регистрозависимость UNIQUE, длина кириллицы, `null` в nullable при PUT, повторный DELETE.

**Технические находки:**
- **`pyproject.toml` с BOM** — `tomllib` падал, `pip install` не работал. Файл перезаписан в UTF-8 без BOM.
- **`pytest` собирал чужие тесты** из `pgsql/pgAdmin 4/...` (22 ошибки collection). Исправлено: `[tool.pytest.ini_options] testpaths = ["tests"]`.
- **Тестовая БД:** `kip_register` не имеет права `CREATE DATABASE`; `kip_register_test` создана суперпользователем кластера.
- **Расхождение источников времени:** `created_at` — серверное `now()`, `updated_at` после исправления Q4 — Python `datetime.now(timezone.utc)`. При развёртывании на другой машине часы должны быть синхронизированы. Альтернатива на будущее — явный `func.now()` в UPDATE.

## 3. Что требует внимания

- **CHANGELOG.** CRUD справочников — первая пользовательская функциональность (API). Файла `CHANGELOG.md` в проекте ещё нет — его надо создать. Строка для дописи: `13.11.2026 | не выпущено | Добавлено | API справочников: создание, чтение, обновление, удаление 18 справочников; аудит изменений (кто, когда)`.
- **Синхронизация часов** при развёртывании (см. раздел 2). Не блокер для разработки.
- **Характеризационные тесты** (тестировщик, ~9 штук) фиксируют поведение реализации, а не контракт. При изменении поведения (например, парсинга `limit`) они упадут — это ожидаемо, не регрессия.
- **`tests/independent/`** — тесты тестировщика теперь часть прогона `pytest tests`. При следующем тестировании — новая папка или суффикс, чтобы не смешивать с текущими.
- **Формат дат** (RFC 822) — не ISO 8601. Для будущего UI может быть неудобно; смена формата — правка контракта, не блокер.
- **Аутентификация** отсутствует — `created_by`/`updated_by` всегда `"system"`. Отдельная задача.
