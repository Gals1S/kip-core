# 3. Организация тестирования

Эта инструкция описывает, как проверять код, который пишут утилиты (когда мы дойдем до этапа написания кода). Мы используем 4 уровня тестирования (из `CORE-ADR-012`).

## 3.1. Уровень 1: Модульные тесты (Unit)
**Кто делает:** ИИ-разработчик.
**Что делает арбитр:** Следит за одним строгим правилом.
- **Правило:** Разработчик может писать тесты, но **не имеет права менять ожидаемые результаты** (assertions) в тестах, чтобы «подогнать» их под свой кривой код. Если тест падает — он должен исправить код, а не тест. Если тест изначально написан неверно, изменение ожидаемых значений разрешает только арбитр.

## 3.2. Уровень 2: Контрактные тесты (Black-box)
**Кто делает:** Отдельный чистый ИИ-чат (не тот, что писал код).
**Что делает арбитр:** Организует процесс.
1. Попросите разработчика сгенерировать «карту контрактов» (список функций с описанием входов, выходов и docstring).
2. Откройте **новый чат**, напишите: *«Ты тестировщик. Работаешь по методу черного ящика. Не видишь код. Пиши тесты только по этим контрактам»*.
3. Передайте ему «карту контрактов».
4. Заберите готовые тесты и отдайте их разработчику, чтобы он запустил их у себя.

## 3.3. Уровень 3: Дымовое и нагрузочное тестирование
**Кто делает:** Core (пишет сценарии), Арбитр (запускает).
**Что делает арбитр:** 
1. Попросите Core написать скрипт (например, на Python или SQL), который имитирует одновременную работу 10 пользователей (нагрузка) или просто запускает базовые операции (дым).
2. Сохраните скрипт в проект утилиты.
3. Запустите его в терминале.
4. Скопируйте результат (успех/ошибки) и отправьте обратно в чат Core.

## 3.4. Уровень 4: Приёмочное тестирование (UAT)
**Кто делает:** Арбитр.
**Что делает арбитр:**
1. Попросите Core составить пошаговый чек-лист (сценарии: «нажать кнопку, ввести неверные данные, проверить ошибку»).
2. Запустите приложение (утилиту).
3. Пройдите по чек-листу как обычный пользователь.
4. Зафиксируйте, где поведение системы не совпало с ожиданиями.

## 3.5. Правило «Evidence Pack» (Доказательства)
Не верьте отчетам ИИ на слово. При приёмке задачи (задания) требуйте доказательства:
- Ссылку на коммит.
- Лог прохождения тестов (скриншот или текст).
- Скриншоты работы интерфейса (для UAT).
