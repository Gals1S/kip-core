# 1. Настройка среды и основные команды

Этот документ — инструкция по установке и использованию основных инструментов проекта. Среда едина для всех утилит экосистемы.

## 1.1. Инструменты

### VS Code
- Установка: Скачать с code.visualstudio.com, установить.
- Расширения (обязательно): В VS Code нажать Ctrl + Shift + X, найти и установить:
  - Markdown All in One (для удобной работы с текстом).
  - Markdown Preview Enhanced (для красивого предпросмотра Ctrl + K V).

### Git
- Установка: Скачать с git-scm.com, установить (настройки по умолчанию).
- Зачем нужен: Git — это «машина времени» для файлов. Он позволяет сохранять контрольные точки (коммиты). Если что-то сломается или удалится, вы сможете вернуться к любой из сохраненных точек.
- Проверка: Открыть терминал в VS Code (Ctrl + ~), ввести `git --version`.

### Total Commander (TC)
- Установка: Скачать с ghisler.com, установить.
- Зачем: Замена Проводника. Удобен для массового копирования файлов, сборки пакетов для чата и быстрой навигации.

## 1.2. Служебные файлы Git

Когда вы работаете с проектом, Git не должен сохранять «мусор» (временные файлы, кэш). Для этого в корне проекта создаются два специальных файла:

1. `.gitignore` — список папок и файлов, которые Git должен игнорировать. 
   Пример: в него всегда добавляют `.venv/` (виртуальное окружение Python), `__pycache__/` (кэш) и файлы `.env` (с паролями).
2. `.gitkeep` — «заглушка». Git по умолчанию не сохраняет пустые папки. Если вам нужна пустая папка (например, `diary/`), вы кладете в нее пустой файл с именем `.gitkeep`, и Git сохраняет эту папку.

## 1.3. Как развернуть Git в новом проекте (Первая настройка)

Если вы начинаете новый проект (например, новую утилиту), сделайте следующее:

1. Откройте папку проекта в VS Code (File -> Open Folder).
2. Откройте терминал (Ctrl + ~).
3. Настройте ваше имя и почту (это делается один раз для всех проектов на компьютере):
   `git config --global user.name "Ваше Имя"`
   `git config --global user.email "ваш@email.com"`
4. Инициализируйте Git в папке проекта (создаст скрытую папку `.git`, которая будет хранить историю):
   `git init`
5. Создайте файл `.gitignore` (через VS Code) и добавьте туда нужные исключения.

## 1.4. Основные команды в терминале VS Code (PowerShell)

Минимальный набор команд для работы.

**Навигация и файлы:**
- `cd папка` — перейти в папку (например, `cd KIP_Core`).
- `cd ..` — подняться на уровень выше.
- `ls` — показать список файлов в текущей папке.
- `cat файл.txt` — вывести содержимое файла на экран.
- `mkdir новая_папка` — создать новую папку.
- `clear` — очистить экран терминала.

**Git (контроль версий и синхронизация с ИИ):**
- `git pull` — **Зачем:** Скачать актуальные изменения из GitHub на ваш компьютер. **Когда:** Всегда в самом начале сессии, чтобы ваша локальная копия совпадала с облачной.
- `git status` — **Зачем:** Проверить, какие файлы изменены или добавлены. **Когда:** Перед коммитом, чтобы убедиться, что вы не забыли ничего важного.
- `git add .` — **Зачем:** Добавить все изменения к следующему коммиту.
- `git commit -m "Текст"` — **Зачем:** Зафиксировать (сохранить) изменения в локальной истории с сообщением. Пример: `git commit -m "26.11.2026: обновлен human-guide"`
- `git push` — **Зачем:** Отправить ваши локальные изменения на GitHub. **Когда:** В конце сессии, после коммита. **Критически важно:** Поскольку ИИ-чаты читают файлы напрямую из GitHub, они не увидят ваших локальных изменений, пока вы не сделаете эту команду.
- `git log --oneline` — **Зачем:** Посмотреть историю коммитов (кратко).
- `git diff` — **Зачем:** Посмотреть, что именно изменилось в файлах (до коммита).

## 1.5. Ежедневный рабочий цикл

1. **Синхронизация (Начало):** Откройте проект в VS Code, откройте терминал и выполните `git pull`. Это гарантирует, что ваша локальная копия идентична облачной перед началом работы.
2. **Работа с ИИ:** Вносите изменения в файлы (копируете тексты, сгенерированные ИИ, или правите их вручную).
3. **Фиксация:** Выполните `git add .`, а затем `git commit -m "ДД.ММ.ГГГГ: что сделано"`.
4. **Публикация для ИИ (Конец):** Выполните `git push`. Только после этого шага ваши изменения становятся видимыми для ИИ-чатов, которые читают файлы из репозитория. Без этого шага чат будет читать старую версию файла.
