## 1. Среда эксплуатации

Общие ограничения для всех инструментов учёта КИП:

- Windows 10/11 x64 (целевая ОС).
- UI через браузер (Chromium: Яндекс.Браузер, Chrome, Edge).
- Без прав администратора.
- Без доступа в интернет (все ресурсы локальные).
- Портативность: перенос на другой ПК копированием папки.
- Без CDN и внешних сервисов в рантайме.

Конкретная архитектура (локальный Flask, клиент-сервер, число
пользователей, топология сети) — в SPEC соответствующей утилиты.

### Среда и контракт — в чём разница

**Среда** (этот раздел) — условия, в которых работают утилиты.
Изменение среды (например, Windows 12) требует адаптации каждой
утилиты, но **не меняет контракт** между ними. Версия контракта
при этом не меняется.

**Контракт** — модель данных (раздел 2 и ADR) и формат обмена
(раздел 3). Изменение контракта — новая версия, утилиты обновляются
осознанно.

## 2. Модель данных

> Полное описание — в ADR. Настоящий раздел — точка входа: перечень
> сущностей и ключевые принципы. При расхождении с ADR прав ADR.

### Сущности

| Сущность | Что это | ADR |
|---|---|---|
| **Проект** | Совокупность приборов, кабелей, помещений, документов | — |
| **Модель прибора** | Справочная запись: название, тип, производитель | ADR-002 |
| **Проектный стандарт** | Состав сигналов и значения по умолчанию для модели на проекте | ADR-002 |
| **Прибор** | Единица оборудования КИПиА: позиция, характеристики, параметры процесса, статус закупки, документы | ADR-002 |
| **Сигнал** | Часть прибора: тип, электрическая реализация, система управления, число жил, уставки | ADR-002 |
| **Логический кабель** | На этапе учёта — связь «прибор → подсистема», связывается с сигналами | ADR-003 |
| **Помещение** | Номер, наименование, палуба, строительный район | ADR-004 |
| **Монтажная группа** | Данные прибора о монтаже: помещение, тип монтажа, ссылка на чертёж | ADR-004 |
| **Документ** | Тип, номер, ревизия, наименование; связывается с приборами | ADR-002 |
| **Справочники** | Стандартизованные значения (IP, Ex, материалы, характеристики, уровни уставок и т.д.) | ADR-002 |

### Ключевые принципы

- **Наследование и переопределение.** Прибор наследует значения
  из проектного стандарта; инженер может переопределить любое
  значение для конкретного прибора. Переопределение видимо
  и отслеживаемо (ADR-002).
- **Логическое и физическое.** На этапе учёта фиксируются логические
  данные (что, куда, зачем). Физическая детализация (марка кабеля,
  шкафы, физические сегменты, монтажные элементы) появляется
  на этапе вывода (ADR-003, ADR-004).
- **Справочники vs свободный ввод.** Стандартизованные коды
  в справочниках; вариативные значения — свободный ввод или
  «справочник + уточнение» (ADR-002).

## 3. Форматы обмена

Обмен между инструментами — только через табличные файлы.

- **Формат:** CSV.
- **Кодировка:** `utf-8-sig` (BOM для совместимости с Excel).
- **Разделитель:** `;`.
- **Структура:** одна строка — одна запись; первая строка — заголовки
  колонок.
- **Состав колонок** — определяется моделью данных (ADR) и источником
  (схема, проект, инструмент). Маппинг колонок на модель — в
  утилите-приёмнике, не в Core. При изменении состава — новая версия
  контракта.
- **Версионирование формата:** формат обмена версионируется вместе
  с контрактом (см. `docs/handover.md`, раздел 7).

Внутренние форматы инструментов (ручной ввод, выгрузка в Excel для
пользователя) — не входят в обмен и описываются в SPEC утилиты.

## 4. Глоссарий

> Термины, одинаковые для всех инструментов экосистемы. Развёрнутые
> определения — в ADR модели данных.

| Термин | Значение |
|---|---|
| **Прибор** | Единица оборудования КИПиА (датчик, клапан, преобразователь). Имеет позицию (`tag`), тип, модель |
| **Позиция** (`tag`) | Уникальное обозначение прибора в рамках проекта |
| **Сигнал** | Часть прибора: вход/выход (AI1, AO1, DI1…), с типом, электрической реализацией, системой управления, числом жил |
| **Уставка** | Пороговое значение сигнала: уровень (HHH…LLL) + число |
| **Модель прибора** | Справочная запись: название, тип, производитель |
| **Проектный стандарт** | Состав сигналов и значения по умолчанию для модели на проекте |
| **Переопределение** | Значение на уровне прибора/сигнала, отличающееся от проектного стандарта |
| **Логический кабель** | На этапе учёта — связь «прибор → подсистема», без физических сегментов |
| **Физический сегмент** | Участок физического кабеля на этапе вывода (прибор → коробка → шкаф); один логический кабель может породить несколько сегментов |
| **Подсистема (система управления)** | РСУ, ПАЗ, ПЛК — система, к которой относится сигнал и в которую идёт логический кабель |
| **Точка подключения** | Шкаф, клеммная коробка, панель. Появляется на этапе вывода |
| **Помещение** | Место установки прибора или шкафа (номер, наименование, палуба, строительный район) |
| **Монтажная группа** | Данные прибора о монтаже: помещение, тип монтажа, ссылка на чертёж |
| **Проект** | Совокупность приборов, кабелей, помещений, документов |
| **Этап учёта** | Стадия фиксации логических данных: прибор, сигнал, логический кабель в подсистему, помещение |
| **Этап вывода** | Стадия наложения физических данных: шкафы, физические сегменты кабеля, марки, крепёж |
| **Логические данные** | Что, куда, зачем (в учёте) |
| **Физические данные** | Марка, размеры, монтаж (на этапе вывода) |

Термины «проектный стандарт», «переопределение», «логическое»,
«физическое», «этап учёта», «этап вывода» раскрыты в ADR модели
данных. Глоссарий — краткая шпаргалка, не замена ADR.
