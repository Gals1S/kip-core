# KIP Core

Общие принципы и модель данных для инструментов учёта КИП

## Функции

Инструменты учёта КИП выполняют три группы функций:

- **Сбор данных.** Извлечение из схем, приём из табличных
  файлов (CSV), ручной ввод через интерфейс.

- **Хранение.** Учёт приборов, сигналов, физических сегментов
  кабелей, помещений и документов; справочники (типы, модели,
  характеристики); история изменений.

- **Вывод.**
  - Подготовка данных для разработки документов (схемы,
    чертежи, спецификации и др.).
  - Выгрузка табличных данных (перечни сигналов, кабельные
    журналы, отчёты).

## Принципы

- **Независимость через файлы.** Инструменты не связаны напрямую:
  нет общего API, нет прямого доступа одного инструмента к базе
  другого. Единственный способ обмена между ними — табличные файлы.
  Общая база данных проекта (доступ по локальной сети) есть только
  у Register — она хранит данные учёта и не является каналом обмена
  между утилитами.

- **Общая модель данных.** Все инструменты работают с одной
  моделью, описанной в Core. Это контракт, а не связь.

- **Логическое и физическое разделены.** Логические данные
  (что, куда, зачем) ведутся при учёте в Register. Физическая
  детализация (марка, размеры, монтаж, сегменты) заполняется
  при подготовке вывода — по правилам, вручную или импортом —
  и тоже хранится в Register. Различие — в том, кто и когда
  заполняет данные, а не в месте хранения. Векторные документы
  формирует Generator.

- **Версионирование модели.** Модель имеет версию. Инструменты
  указывают, с какой версией работают. При изменении модели —
  новая версия, инструменты обновляются осознанно.

Полный состав документации, роли файлов и папок, порядок чтения
для нового участника — в `handover.md`, раздел 5. Там же — какие
документы являются источником правды, а какие — историей
