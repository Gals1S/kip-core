# CORE-ADR-013: Аудит справочников

**Проект:** KIP_Core
**Статус:** см. `decisions/CORE-ADR-REGISTRY.md`
**Дата:** 13.11.2026
**Связанные документы:** `REG-REQ-001-refs-audit.md`, `CORE-TASK-003-refs-crud.md`

---

## Контекст

Справочники (типы приборов, модели, IP, Ex и т.д.) — фундамент проекта. На них ссылаются приборы и сигналы. Изменение записи справочника (например, кода IP или числа жил) влияет на все связанные данные. 

В модели Core v1.1 аудит (поля `created_by`, `updated_by` и т.д.) был предусмотрен только для приборов, сигналов и физических сегментов. Справочники оставались без аудита, что создавало разрыв в отслеживаемости изменений в многопользовательской среде.

## Решение

1. Во все 18 таблиц справочников добавляются поля аудита: `created_by`, `created_at`, `updated_by`, `updated_at`.
2. Полная история изменений (отдельные таблицы логов, как для переопределений приборов) для справочников **не ведется**. Фиксируется только факт последнего изменения.
3. Внедрение аудита объединяется с заданием на написание CRUD (`CORE-TASK-003`), чтобы избежать двойной работы по переписыванию кода.

## Последствия

- Требуется обновление архитектурного документа `CORE-ARCH-data-model.md`.
- В Register создается новая миграция Alembic для добавления колонок.
- Код CRUD в Register сразу пишется с учетом автоматического заполнения полей аудита.
